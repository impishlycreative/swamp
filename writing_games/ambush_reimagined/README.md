# Ambush — Reimagined

This comparison version was created using the revised learning-game methodology. The original Ambush game is intentionally left untouched.

## Learning core

**Objective:** Practise adapting an already-established scene when a credible complication changes the conditions of that scene.

**Player behaviour:** Establish a scene, commit to an initial direction, receive an ambush that attacks an explicit assumption, adapt without erasing prior choices, and identify the consequence that should persist.

**Mechanic:** Timed interruption plus persistent story-state changes.

**Feedback:** The game shows which story conditions changed and explains why the complication follows from the setup. It does not assign a generic quality score.

**Transfer:** Players discuss how to seed complications, preserve causality, and carry consequences forward in their own fiction.

## Quality rules

- Ambushes must grow from existing or plausibly latent information.
- Random escalation is not sufficient.
- The player performs the important reasoning; the game does not solve the scene.
- Consequences must persist rather than vanish after the surprise.
- Scenarios should vary structurally, not just by names or setting.
- Feedback describes effects and trade-offs rather than declaring subjective craft choices correct or incorrect.
- Group discussion and reflection are part of the learning loop.
